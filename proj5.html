MODULE_02   TB TOPOLOGY

TESTBENCH ARCHITECTURE

Pure UVM hierarchy — no hand-made mailboxes. mem_test builds mem_env; the env holds mem_agent (sequencer, driver, monitor, coverage) and mem_scb. Components talk over seq_item_port and uvm_analysis_port.

MODULE_03   OPERATION

VERIFICATION FLOW

⌘
SEQUENCE
  • Test starts a mem_seq on env.agent.sqr, or sets it as default_sequence
  • `uvm_do_with randomizes wr_rd_i, addr_i, wdata_i
  • Read sequences reuse the written addr_i
  • Objection raised in pre_body, dropped in post_body
▶
DRIVE
  • mem_drv pulls with get_next_item()
  • Drives addr_i, wr_rd_i, wdata_i through drv_cb
  • Asserts valid_i, waits for ready_o
  • Captures rdata_o on reads, then item_done()
◈
SAMPLE
  • mem_mon is passive, samples via mon_cb
  • Captures a transfer when valid_i && ready_o
  • Rebuilds a mem_tx from bus activity
  • Broadcasts with ap_port.write() to scoreboard and coverage
✓
CHECK
  • mem_scb keeps a mem[*] shadow model
  • On write: mem[addr_i] = wdata_i
  • On read: compares rdata_o to mem[addr_i]
  • Updates matching / mismatching, prints in report_phase
⬡
COVER
  • mem_cov is a uvm_subscriber #(mem_tx)
  • ADDR auto-bins + WR_RD HIGH/LOW
  • WR_RD_X_ADDR cross closes every op × address region
  • Sampled in write() for every observed transfer
MODULE_04   TESTPLAN

UVM TESTCASES

TC_01
1W
Single randomized write. Baseline sanity check for one valid → ready handshake.
Test: wr_test · write ×1
TC_02
5W
Five writes to distinct addresses, started through the sequencer's default_sequence.
Test: wr5_test · write ×5
TC_03
NW
N randomized writes, where N is common::N (default 5).
Test: nwr_test · write ×N
TC_04
1WR
One write followed by one read to the same address — directed read-after-write check.
Test: wr_rd_test · write(A) → read(A)
TC_05
5WR
Five writes to distinct addresses, then five reads back from the same addresses.
Test: wr5_rd5_test · write ×5 → read ×5
TC_06
NWR
Default test. N writes to distinct addresses, then N reads of the same addresses — full read-after-write closure, 100% coverage.
Test: nwr_nrd_test · write ×N → read ×N
⚙ Default test is set in run_test("nwr_nrd_test") inside 2_mem_top.sv. Pick another with +UVM_TESTNAME=<test>. Transaction count common::N lives in 15_mem_common.sv.
MODULE_05   PROTOCOL CHECKS

SVA ASSERTIONS

Four properties live inside 11_mem_intf.sv and run live in every test. All use disable iff(rst) and are gated with valid_i, so idle bus cycles are never checked.

wr_addr_unknownp1
(valid_i && wr_rd_i) |-> !$isunknown(addr_i)
During a write, the address must be a known value, never X or Z.
wr_data_unknownp2
(valid_i && wr_rd_i) |-> !$isunknown(wdata_i)
During a write, the write data must be a known value.
rd_addr_unknownp3
(valid_i && !wr_rd_i) |-> !$isunknown(addr_i)
During a read, the address must be a known value.
rd_data_unknownp4
(valid_i && !wr_rd_i) |=> (ready_o && !$isunknown(rdata_o))
One clock after a read request, ready_o must be high and rdata_o must be known — matches the DUT's registered latency.
